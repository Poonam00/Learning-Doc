MODULE 1: Claude and Model Foundation

# Behavioral Properties of Claude
1. Responses vary each time
2. Confident tone is not a sign of accuracy
3. Context is a budget
4. Knowledge has a training boundary
5. Configured workflows/procedures reduces output variance but does not eliminate it

# Entry Point of Calude
1. Chat: task starts and end within the session. Good for one-off question. Single use
2. Project: Recurring work. Same knowledgeable each time
3. Artifact: Creates standalone content that show up in separate panel next to chat like diagram, document, slide, spreadsheet etc 
4. Research: available of paid plan. For deep analysis

# Capability Layer
- Entry points determine where you work. The capability layer determines what Claude can do within that entry point.
- The Four Layer Model:
  1. Project:  backdrop knowledge as a context
  2. Skill: defining workflow that handles repeated task
  3. Code Execution: it should verify the computation to cause consistent output
  4. Memory: relevant information carry forward across sessions
- Each layer is independent. We can used any combination to get our work done.
- SKILL: skills are reusable procedures. Built-in skill are also available. Lives at account level. For example: workflow for editing spreadsheet, word doc etc. Skill are used for repeatative task but each time it can produce varied result.
- CODE EXECUTION: Code Execution is Claude's sandboxed computation environment. It could be provided by your partnered company as well. For the task where code-execution/computation is required, Claude up the sandbox and execute the code and return output. For example: any numeric calculation, output is some file, output is chart or diagram.
- MEMORY: memory retains work related facts across sessions. Memory not reviewed frequently can be misleading so it's important to curate it on regular basis. Incognito mode keeps session out of memory and chat history.

# Choosing Models
1. Haiku - speed and volume; use if variance if output is fine
2. Sonnet - professional drafting;
3. Opus - slow; complex; reasoning

# Conversation Hygiene
- each Claude conversation has finite working-memory limit. After this limit, the conversation is summarized and the old conversation is there in the history for reference but not in memory. Sometime when we chat for long duration, the Claude forget the initial instructions because of this
- measures to take when this happens:
  1. RESTART a new conversation
  2. SUMMARIZE current conversation and paste in new chat
  3. PERSIST the information that can be used in further session in the memory or the knowledge base
- Memory Curation: Memory serves best when curated. Try to keep the memory upto-date.
- Usage Limit: follow the above measures to stay within the limit, otherwise the task will remain incomplete.


MODULE 2: Prompting and Task Execution

# 5 component of Prompt
  1. Role : what role you want Claude to be for this task, an it guy, financial expert, etc
  2. Context : what background you want Claude to have, what audience this output cater to
  3. Task : Clear instruction such as Summarize, compare, draft, identify
  4. Constraints : The boundaries like length, tone, what to include, what to exclude
  5. Output Format : result format like table, bullet point, a draft email, paragraph
Based on your task you can choose which all component you need
Description/context: Providing Claude with the Access to files, inbox, diagrams etc.
Weak Prompt: missing context gives  generic answer, unclear task instruction gives wrong output format, absent constraints provide wrong length or tone. 

For Example: 
WEAK PROMPYT:
"Write a summary of our quarterly operations." 
-> will give generic answer, not actually usable

STRONG PROMPT:
"You are an operations analyst (role). I am preparing a one-page update for our regional director, who cares about throughput and cost, not process detail (context and audience). Summarize the attached Q3 operations data (task), covering only the three metrics that moved more than 10 percent against target (constraint). Format as a short headline followed by three bullet points, each one sentence (output format)."
->but if you provide an explicit prompt with all the 5 component provided, will give actual usable output. 

# Task Decomposition
- Splitting a large/multi-step problem statement into discrete, ordered steps, that can be run sequentially 
- This helps when the flow of execution is needed for audit instead of direct response.
- Also if any step fails in between, we can catch it and correct it
- Keep sequential steps in one conversation so that each step can refer the prior result. If any step is independent use a new conversation or when the conversation has gone long and is degrading the output.

# Iterating prompts to improve Output
- this means, resending the prompt in a conversation which initial prompt missed
- For example- Draft an email on so and so, the Claude draft the email, Next give a prompt to give a subject line.
- Another example - Create a report of performance for a team, Claude give generic answer and we recognized we need result in which format, which team, so add those details.
- Iterating the prompts is to accurate the output which is need further no action.
- It basically means chatting to Claude and keep on giving relevant instruction to produce more accurate result.

# Adapting Strategy to task type
- the 5 component cannot be applied to all the kind of tasks
- For Analysis:  give tight criteria, scope, what to measure, what standard to follow
- For Research: give boundary, questions, access to web or not
- For Drafting: give audience, tone, format
- For Brainstorming: give goal and boundary, keep loose constraint, give freedom to explore and innovate
